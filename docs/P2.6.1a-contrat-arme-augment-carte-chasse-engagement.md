# P2.6.1a — Contrat de frontière : Arme / Augment / Carte Chasse / Engagement

**Statut : DRAFT à valider avant implémentation**

## 1. Objectif

Fixer la propriété de chaque mécanique de chasse avant de créer les cartes et actions Foundry.

Le modèle sépare quatre couches :

1. **Arme native Daggerheart** — l'objet utilisé pour attaquer.
2. **Augment** — modification persistante et installable de cette arme.
3. **Carte Chasse** — technique apprise par le chasseur, utilisable sous contrainte d'arme.
4. **Engagement** — protocole commun de coopération pendant la chasse.

Aucune couche ne doit absorber les responsabilités d'une autre simplement parce que son implémentation Foundry est plus facile.

---

## 2. Arme native Daggerheart

L'arme reste un `Item` Weapon Foundryborne natif.

Elle porte notamment :

- trait d'attaque ;
- portée ;
- dégâts ;
- burden ;
- tier ;
- propriétés/features intrinsèques de l'arme ;
- état d'équipement ;
- Augments installés via le Toolkit.

Une arme de chasse n'est donc **pas un nouveau type d'Item**.

### Règle de frontière

Une propriété appartient à l'arme lorsqu'elle décrit **ce que l'objet est ou fait intrinsèquement**, indépendamment de la technique connue par son porteur.

Exemples :

- une Greatsword a son profil d'attaque natif ;
- une Lance possède ses propriétés intrinsèques ;
- `Force` modifie durablement l'arme mais reste un Augment installé ;
- `True Charge` n'est pas une propriété intrinsèque de toutes les Greatswords.

---

## 3. Augment

Un Augment est une modification persistante de l'instance d'arme.

Le modèle Motherboard validé reste la primitive :

```text
weapon
└── flags.daggerheart-campaign-toolkit.weaponAugments
    ├── slots
    ├── crafted[]
    ├── installed[]
    └── structural{}
```

### Propriétés

Un Augment :

- est crafté/débloqué séparément ;
- occupe éventuellement un slot ;
- peut être installé/désinstallé ;
- suit l'instance d'arme, pas le personnage ;
- peut matérialiser une Weapon Feature, un ActiveEffect, une action ou une mutation structurelle ;
- peut être rematérialisé avec `weaponAugmentState.resync()`.

### Règle de frontière

Si deux exemplaires identiques d'une arme peuvent légitimement avoir des propriétés différentes à cause du craft, la propriété est candidate à être un **Augment**.

---

## 4. Carte Chasse

Une Carte Chasse représente une **technique maîtrisée par le chasseur**.

Elle appartient à la progression Chasse du personnage et non à l'instance physique de son arme.

Exemples envisagés :

- Greatsword — `True Charge` ;
- Lance — technique défensive liée à l'Engagement ;
- techniques spécialisées Opener ;
- techniques spécialisées Finisher ;
- techniques spécialisées Support.

### Contrainte d'arme

Une Carte Chasse peut déclarer une condition d'utilisation :

```json
{
  "requires": {
    "weaponFamily": ["greatsword"]
  }
}
```

Cette contrainte signifie :

> le personnage connaît la technique, mais ne peut l'utiliser que lorsqu'il remplit sa condition d'arme.

Changer d'arme ne supprime donc pas la carte du personnage.

### Limite de préparation

Contrat actuel :

**maximum 2 Cartes Chasse liées à l'arme préparées/actives à la fois.**

Cette limite concerne les techniques disponibles en chasse, pas les Augments installés sur l'arme.

La représentation Foundry exacte de cette préparation sera décidée en P2.6.3/P2.6.4.

---

## 5. Engagement

Engagement est une règle de chasse commune. Il n'appartient ni à une arme ni à une Carte Chasse particulière.

Séquence conceptuelle :

```text
Opener
  │
  ├── dépense 2 Hope
  ├── effectue son action
  └── génère X Opportunités
            │
            ├── dégâts / Effet
            │
            └── désigne un Finisher
                       │
                       └── conversion des Opportunités

Support
  └── intervient autour de l'Opener ou du Finisher
```

Contrat Tier 1 actuellement retenu :

- base `X = 2` Opportunités ;
- l'Opener dépense 2 Hope pour ouvrir l'Engagement ;
- le Finisher désigné convertit les Opportunités ;
- 1 Opportunité peut alimenter les dégâts ;
- les Effets utilisent leur propre coût en Opportunités ;
- le critique du Finisher permet Effet + dégâts selon la règle d'Engagement ;
- les Opportunités non converties disparaissent à la fin de la chaîne ;
- Support peut notamment dépenser 1 Hope pour infliger `-1d4` au jet d'attaque du monstre contre un personnage engagé, selon la règle validée.

Les détails de résolution seront cristallisés séparément en **P2.6.2**.

### Règle de frontière

Une Carte Chasse peut **modifier ou exploiter** Engagement.

Elle ne doit pas réimplémenter son propre système parallèle d'Opportunités.

Exemple :

```text
Engagement définit :
"une Opportunité peut être convertie"

True Charge définit :
"voici une conversion spéciale disponible avec une Greatsword"
```

---

## 6. Progressions séparées

Le personnage possède conceptuellement deux axes :

```text
Personnage
├── progression Daggerheart
│   ├── classe
│   ├── sous-classe
│   └── Domain Cards
│
└── progression Chasse
    ├── techniques
    ├── rôles/capacités de chasse
    └── Cartes Chasse
```

La progression Chasse ne doit pas consommer artificiellement les choix normaux de Domain Cards Daggerheart.

Une Carte Chasse pourra éventuellement **réutiliser la présentation ou certaines primitives techniques** des cartes Foundryborne, sans devenir pour autant une Domain Card canonique.

---

## 7. Rôles de chasse

Les rôles déjà envisagés restent une couche de compétence du groupe :

- Naturaliste ;
- Traqueur ;
- Tacticien ;
- Cuistot ;
- Extracteur ;
- Opener ;
- Finisher ;
- Support.

Les cinq premiers concernent principalement la boucle d'exploration/préparation/loot.

Opener, Finisher et Support décrivent des interactions avec Engagement.

Un personnage n'est pas nécessairement enfermé définitivement dans un rôle : le rôle peut servir de qualification, de spécialisation ou de capacité selon la future progression.

**P2.6.1a ne fixe pas encore le mécanisme d'acquisition des rôles.**

---

## 8. Test de propriété

Pour toute nouvelle mécanique, appliquer dans cet ordre :

```text
Est-ce une propriété intrinsèque de l'objet ?
        → Weapon Feature native

Est-ce une modification craftée de cette instance d'arme ?
        → Augment

Est-ce une technique connue par le personnage et conditionnée par son équipement ?
        → Carte Chasse

Est-ce une règle de coopération commune à la chasse ?
        → Engagement
```

Une mécanique peut interagir avec plusieurs couches, mais une seule doit rester sa source d'autorité.

---

## 9. Exemples

### Force

```text
+1 dégâts
```

→ **Augment**.

Le bonus appartient à cette arme précise.

### Scope

```text
Portée +1 étape
```

→ **Augment structurel**.

La portée de l'instance d'arme est réellement modifiée.

### True Charge

```text
Conversion spéciale d'Opportunités avec une Greatsword
```

→ **Carte Chasse**.

La technique appartient au chasseur et exige une famille d'arme compatible.

### Lance défensive

```text
Technique permettant au chasseur de mieux protéger un personnage engagé
```

→ **Carte Chasse** si elle constitue une technique apprise.

La réduction générique `-1d4` du Support reste, elle, une règle d'**Engagement**.

### Opportunités

→ **Engagement**.

Elles ne sont ni stockées dans l'arme ni acquises comme Augments.

---

## 10. Conséquence pour Foundry

Architecture cible :

```text
Actor
├── Daggerheart progression
├── Hunting progression (Toolkit)
│   ├── knownCards[]
│   └── preparedWeaponCards[]   # max 2
│
└── Items
    └── Weapon
        ├── native weapon data
        ├── native Weapon Features
        └── Toolkit Augment state
```

Engagement doit disposer de son propre état de résolution temporaire et ne doit pas être persisté comme propriété permanente de l'arme.

Le modèle exact de cet état temporaire sera défini en P2.6.2.

---

## 11. Critères de validation P2.6.1a

P2.6.1a est GREEN si les décisions suivantes sont acceptées :

- Weapon reste natif Foundryborne.
- Augment appartient à l'instance d'arme.
- Carte Chasse appartient au chasseur.
- Une Carte Chasse peut imposer une contrainte de famille d'arme.
- Maximum 2 Cartes Chasse liées à l'arme sont préparées/actives.
- Engagement est un système commun distinct.
- Les Cartes Chasse exploitent Engagement au lieu de le dupliquer.
- Progression Chasse et progression Domain Daggerheart restent distinctes.
- La source d'autorité d'une mécanique est déterminée par le test de propriété.

Après validation : **P2.6.2 — contrat mécanique complet d'Engagement**.
