# P2.3.3k-fix1 — Embedded Feature template leakage

## Problème

P2.3.3k créait correctement les Features embarquées depuis les données source, mais l'audit signalait systématiquement `template automation/resource/effect leakage`.

La cause est double :

1. le template SRD natif de type `feature` transporte des champs d'automatisation propres au document cloné ;
2. Foundryborne rematérialise certains champs neutres (`actions`, `resource`, `effects`) sous forme de DataModel/TypedObject même quand l'importeur les vide. Un simple test « non vide » produit donc des faux positifs.

## Correction

- `pilot-import.mjs`
  - version de mapping `P2.3.3k-fix1` ;
  - suppression des payloads `system.actions` et `system.resource` du template cloné avant création ;
  - `effects` forcé à une collection vide ;
  - aucun mapping automatique supplémentaire n'est inventé.

- `semantic-audit.mjs`
  - construit un Feature natif minimal comme baseline neutre ;
  - compare les fingerprints normalisés de `actions`, `resource` et `effects` à cette baseline ;
  - ne signale désormais que les différences sémantiques réelles ;
  - le message indique le ou les champs fautifs.

- `full-import.mjs`
  - version de mapping portée à `P2.3.3k-fix1` pour forcer la reconstruction des documents gérés.

## Validation attendue

Après réimport complet puis audit :

- 1012 documents gérés ;
- 0 provenance issue ;
- 0 repeated template fingerprint ;
- 0 `template semantic leakage` sur les embedded Features ;
- `statIssues = 0` si aucun autre problème indépendant n'est présent.

Le nombre de mapping gaps ne doit pas augmenter à cause de ce fix.
