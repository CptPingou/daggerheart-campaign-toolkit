# P2.3.3o-a — Equipment feature integrity

## Scope

Repair the equipment feature extraction debt discovered during P2.3.3o and remove duplicate visual rendering of mapped equipment features in Foundryborne.

## Data repairs

Compared against the SRD 2.0 equipment tables, 65 deterministic truncations are repaired:

- 44 standard weapon rows
- 3 Combat Wheelchair rows
- 18 armor rows
- 0 supplemental campaign weapon rows

Affected semantic families include Heavy, Cumbersome, Flexible, Very Heavy, Protective, Barrier, Paired, Focused, Double Duty, Brave, Gilded, Vigilant and Channeling.

Examples:

- `Heavy: −1 to` → `Heavy: −1 to Evasion`
- `Cumbersome: −1 to` → `Cumbersome: −1 to Finesse`
- `Flexible: +1 to` → `Flexible: +1 to Evasion`
- `Paired: ... targets within` → `Paired: ... targets within Melee range`

The extractor now includes `equipment_feature_tails_complete` as a validation gate. The repair rules are deliberately narrow and only restore suffixes explicitly established by the SRD tables.

## Foundry display deduplication

When an equipment feature has a configured Foundryborne feature key, Foundryborne already renders that feature. The adapter no longer appends the same source rule to the generic Item description. Source semantics remain in DH-DATA and in the registered feature catalog/provenance.

This fixes displays such as Talon Blades showing `Brutal` twice while preserving legitimately distinct features that happen to share a title elsewhere. Identity is not deduplicated by title alone.

## Expected validation

Run the extractor first, then rebuild the canonical payload with the existing export step used for P2.3.3, copy the toolkit patch, refresh Foundry, and run full import + semantic audit.

Expected structural counts remain unchanged: 1012 top-level canonical documents and 16 Blood Hunter support features. The current 334 automation classifications are intentionally not reclassified in this patch; P2.3.3o-b will analyze the now-clean feature corpus.
