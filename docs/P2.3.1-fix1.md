# P2.3.1 fix1

Observed on Foundry 14.367 / Daggerheart 2.8.2:

- incomplete ActionField validation when creating hand-built documents;
- adversary `type: "Solo"` rejected;
- environment `type: "Exploration"` rejected;
- partial result: 4 Items / 0 Actors.

## Correction

The importer no longer invents a Foundryborne document schema.

For every pilot entity it now:

1. finds a valid SRD document of the same native Foundryborne type;
2. clones its complete source data;
3. removes identity/storage metadata;
4. overlays only the DH-DATA fields already mapped;
5. normalizes enum-like strings to lowercase;
6. deliberately leaves complex ActionField data native for this pilot.

This is safer against Foundryborne schema evolution and becomes the importer doctrine for P2.3.

## Retest

Replace only the files from this patch, reload Foundry, then run:

```js
await game.modules.get("daggerheart-campaign-toolkit").api.importPilot();
```

Expected:

```text
pilotItems: 5
pilotActors: 2
```

Then open all seven documents. If GREEN, attack/action mapping becomes a separate mapping step instead of being mixed into document creation.
