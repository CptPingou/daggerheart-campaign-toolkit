# P2.3.3l — Equipment feature catalog

## Goal
Resolve the explicit `:catalog` gaps for source weapon/armor features without inventing automation.

## Behavior
Before building the 1012 mapped documents, the full importer scans weapon and armor source features.

- Exact Foundryborne/native feature names continue to use the native catalog entry.
- A source feature missing from Foundryborne is registered in the official Foundryborne Homebrew equipment-feature catalog.
- Toolkit-created keys are stable and namespaced with `dctSource_...`.
- Existing native or user-defined homebrew entries are never overwritten.
- Registered source-only catalog entries contain only `name`, source `description`, `actions: []`, and `effects: []`.
- The importer still appends each item's exact source feature text to the item description, so variant wording/values remain item-specific.
- Missing behavior remains explicit as `system.weaponFeatures:automation` / `system.armorFeatures:automation`.

## Expected semantic audit
The two catalog rows should disappear:

- `weapon / system.weaponFeatures:catalog`: 55 -> 0
- `armor / system.armorFeatures:catalog`: 1 -> 0

Those 56 documents are intentionally reclassified as automation gaps, therefore total mapping gaps should remain **343**:

- weapon automation: 214 -> 269
- armor automation: 64 -> 65

No semantic gap is hidden; this milestone only closes catalog identity.
