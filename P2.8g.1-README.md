# P2.8g.1 — Domaine Chasse natif Foundryborne

Correction du blocage `Character does not have the domain`.

Cause identifiée : les 8 cartes Monster Hunter avaient hérité `system.domain:
"valor"` du spécimen utilisé pour leur création. Elles utilisent désormais
`system.domain: "hunt"`.

Le patch enregistre aussi `hunt` comme domaine homebrew natif Foundryborne via
le setting Homebrew du système. Foundryborne calcule les domaines autorisés
d'un personnage depuis `system.domains` de sa classe ; le Toolkit expose donc
un grant/revoke explicite sur l'Actor, sans modifier les classes sources.

## Validation

Après extraction + F5, GM :

```js
const api = game.modules.get("daggerheart-campaign-toolkit").api;
console.log(api.monsterHunterHuntDomain.status());
```

Attendu : `registered:true`, `visible:true`, `green:true`.

Sélectionner le PJ :

```js
const actor = canvas.tokens.controlled[0]?.actor;
console.log(actor.system.domains);
console.log(await api.monsterHunterHuntDomain.grant(actor));
console.log(actor.system.domains);
```

Attendu : `hunt` apparaît en plus des domaines normaux du PJ.

Les 8 cartes ont changé de domaine ; resynchroniser :

```js
const before = await api.autonomousSourceStatus();
console.log(before.expected, before.actual, before.green);
console.log(before.packs["dh-domain-cards"]);

await api.syncAutonomousSources();

const after = await api.autonomousSourceStatus();
console.log(after.expected, after.actual, after.green);
console.log(after.packs["dh-domain-cards"]);
```

Attendu après sync : `811 811 true`, `dh-domain-cards 239/239`.

Vous pouvez alors glisser `Ouverture`, `Conversion` ou `Appui défensif` sur le
PJ : Foundryborne doit reconnaître `hunt` dans les domaines du personnage.

Enfin :

```js
console.log(api.monsterHunterActorLoadout.inspect(actor));
console.log(api.monsterHunterActorLoadout.capabilities(actor));
```

Pour retirer ultérieurement l'accès Chasse :

```js
await api.monsterHunterHuntDomain.revoke(actor);
```
