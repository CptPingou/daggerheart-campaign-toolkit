# P2.8g.2a — Generic Toolkit domain-card bridge

Correction fondée sur le bridge réellement présent dans le Toolkit.

Le `_preCreate` était déjà intercepté, mais uniquement pour l'ancien marqueur
`contextualCard` du domaine Hunting. Le bridge reconnaît maintenant aussi
toute carte portant :

`flags.daggerheart-campaign-toolkit.toolkitCard.eligibility = "toolkit"`

avec une `family`.

Pour ces cartes seulement, il conserve la validation héritée Daggerheart,
la présence d'une classe, le contrôle de doublon et le comportement de
loadout natif, mais omet le test « la classe possède ce domaine ».

Les domain cards ordinaires continuent intégralement dans le `_preCreate`
Foundryborne original.

Compatibilité : l'ancien `contextualCard` Hunting reste accepté pendant la
migration.

`importToolkitCard()` est également corrigé : si Foundry rejette réellement
la création et ne renvoie aucun Item, l'API renvoie désormais
`green:false`, `imported:false`, `reason:"embedded-create-rejected"`.

```js
const api = game.modules.get("daggerheart-campaign-toolkit").api;
const actor = canvas.tokens.controlled[0]?.actor;
const pack = game.packs.get("daggerheart-campaign-toolkit.dh-domain-cards");

const opening = docs.find(d => d.name === "Ouverture");
console.log(api.toolkitCardFamilies.metadata(opening));
console.log(await api.toolkitCardFamilies.importCard(actor, opening));
console.log(api.toolkitCardFamilies.validateLoadout(actor, "hunt"));
console.log(api.monsterHunterActorLoadout.inspect(actor));
```

- `itemId` non null

- l'Actor conserve exactement ses deux domaines Daggerheart.
