## Wiring

`Ouverture` now owns a real Foundryborne `attack` ActionField action with stable id
`MHOPENACTION0001`.

The source card also carries the existing Engagement binding:

`flags.daggerheart-campaign-toolkit.engagementActions.MHOPENACTION0001.role = "opener"`

Therefore the existing `createChatMessage` Opener hook can recognize the Duality
message without a separate runtime `markAction()` step.

The action itself has no Hope cost and no damage payload. The existing Opener
resolver remains the sole owner of the 2 Hope cost and Opportunity mutation.

`importToolkitCard()` now mirrors the validated autonomous-source workaround:
Toolkit-authored domain-card actions are materialized after embedded Item creation
through `item.update({"system.actions": ...})`.

## Validation

1. F5.
2. Run `await api.syncAutonomousSources({ force: true })`.
3. Remove/re-import `Ouverture` on the test actor (an already embedded copy predates
   the new action).
4. Open Loadout → Chasse → Ouverture and click its action against a target.
5. Inspect the latest Duality message with `api.engagementOpener.inspectOutcome(msg)`.

Expected before resolving message-shape edge cases: a real Duality roll is emitted
and the Opener hook recognizes the action as role `opener`.
