# P2.8m — Reconstruction mécanique des cartes de domaine

Cette passe ne modifie pas le compendium ni les sources automatiquement.

Elle lit les 210 cartes FR du Toolkit et les 210 cartes natives `daggerheart.domains`,
réutilise exactement le matching P2.8l.1 validé, puis construit un fichier source autonome
où seuls `system.actions` et `effects` sont repris de la carte native correspondante.

Conservé depuis le Toolkit :
- `_id`
- nom / description FR
- image Toolkit
- flags de propriété / canonicalSourceId
- autres champs système FR

Repris du natif :
- `system.actions`
- `effects`

Le reconstructeur réécrit les références explicites vers la carte native elle-même et
refuse le téléchargement si une référence `Compendium.daggerheart.domains...` subsiste.

## Test

Après F5 :

```js
const api = game.modules.get("daggerheart-campaign-toolkit").api;
const { report } = await api.reconstructNativeDomainCardMechanics();
report;
```

Attendu :
- toolkitCards: 210
- reconstructed: 210
- unresolved: 0
- cardsWithActions: 190
- cardsWithEffects: 106
- cardsWithAnyMechanics: 204
- externalNativeReferences: 0
- green: true

Si GREEN, le navigateur télécharge automatiquement :
`dh-domain-cards.reconstructed.json`

Ce fichier est l'artefact intermédiaire à réinjecter dans
`data/core/fr/dh-domain-cards.json` après contrôle. Il rend ensuite la mécanique
versionnée dans le Toolkit, sans lecture runtime de `daggerheart.domains`.
