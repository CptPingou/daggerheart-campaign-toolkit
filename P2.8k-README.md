# P2.8k — Opener Duality Resolution v0.2

Changed file only:
- `scripts/engagement-opener.mjs`

Implements the current Monster Hunter v0.2 Opener table:

| Duality outcome | Opportunity | Monster reaction |
|---|---:|---|
| Critical | +3 | no |
| Success + Hope | +2 | no |
| Success + Fear | +2 | yes |
| Failure + Hope | +2 | yes |
| Failure + Fear | +1 | yes |

Important:
- Opportunity remains written only through the Toolkit Opportunity API.
- The reaction is exposed as `reactionRequired`; this patch does not yet execute the monster attack.
- If the current Foundryborne Duality message shape cannot be identified safely, the resolver stops with `duality-outcome-unresolved` and does not alter Opportunity.
- `inspectOutcome(message)` is exposed on the Opener API for validation.
- Existing hit-target success detection is retained only as a compatibility fallback.

## First validation

Make one real marked Opener roll, then on its ChatMessage:

```js
const api = game.modules.get("daggerheart-campaign-toolkit").api;
const msg = game.messages.contents.at(-1);
console.log(msg);
console.log(api.engagementOpener.inspectOutcome(msg));
```

Send the `inspectOutcome` result. It lets us lock the exact Foundryborne 2.9.4 Duality fields before removing compatibility fallbacks.
